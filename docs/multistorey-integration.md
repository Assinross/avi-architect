# Интеграция поэтажного планировщика в Avi Architect

## Выявленное состояние репозитория на 2026-11-22

- `src/model.ts`: `BuildingModel` — `purpose`, `seed`, `walls`, `openings`; прямоугольный контур и смета по одной площади.
- `src/editor.ts`: `History` / SVG план, инструменты wall/door/window/remove, одна поверхность и общая история Undo/Redo.
- `src/rendering/building.ts`: `house(model, palette, showRoof, theme)` строит стены, один пол и одну двускатную крышу.
- `src/rendering.ts`: `Valley.city` и `Valley.preview` вызывают `house`; NPC привязаны к входной двери первого этажа.
- `src/storage.ts`: конверт `version = 1`, ключ `architects-of-time.valley`; два исходных назначения `home`, `bakery`.
- `tests/model.test.ts` и `tests/browser/chapter.spec.ts` — регрессионные тесты первой главы.

**Ничего из этих файлов пакет не заменяет.** Следующие действия должны идти отдельными коммитами, чтобы не повредить два действующих заказа.

## Этап A — контракт модели

1. Выдели `src/multistorey.ts` как чистый модуль геометрии. При интеграции импортируй общие типы `Point/Wall/Opening` из `src/model.ts` вместо дублирования; у них одинаковая структура, но массивы точек в исходном типе изменяемые. Избегай небезопасных приведения типов, используй явные адаптеры.
2. Расширь `BuildingModel` совместимо, добавив **опциональную** поэтажную схему: `floors?: FloorPlan[]`, где `floors[0]` представляет первый этаж. Нельзя одновременно иметь рассинхронизированные `walls/openings` и `floors[0]`: либо перейти на единственный источник данных и адаптер v1, либо сохранить первые поля только как интерфейс доступа. Предпочтительнее единый канонический объект `floors` с адаптером чтения наследия.
3. В `History` редактирование должно относиться к *активному этажу*: добавление/удаление наружных стен, перегородок, проёмов, лестницы, смена размеров, копирование предыдущего этажа и удаление только последнего. Undo/Redo сохраняет **весь** чертёж, не отдельный этаж.
4. Сохрани правила первых заказов: их площадь — площадь первого этажа, их исходный бюджет 500/700. Многоэтажная стоимость может использоваться в свободной мастерской или новых заданиях с отдельными бюджетами. Старые расчёты одноэтажного дома **должны оставаться равны прежним**.

## Этап B — интерфейс редактора

1. В `src/editor.ts` добавь вертикальную панель этажей и текущий этаж, "+ Этаж", "Удалить верхний". Выбор этажа сохраняй в UI или черновом состоянии, но не в дорогостоящем 3D-графе.
2. Рисуй нижний план полупрозрачным контуром (без захвата кликов); сверху — стены и проёмы текущего уровня. Перегородки — отдельный инструмент и коллекция. Нужны корректные Т-примыкания.
3. Лестницу ставь как элемент **между** этажами; показывай её на обоих планах, на нижнем — стрелка вверх, на верхнем — проём/"вниз". Корректность проверяй по `stairRect()` на двух этажах и по коллизиям с перегородками.
4. Смета показывает этажную площадь, общую площадь, стены, перегородки, проёмы, перекрытия, крыши, лестницы и колонны. Предупреждения `validate()` группируются по этажам. Для многоэтажного свободного режима не ограничивай стоимость контрактом задания.
5. Все инструменты работают с сенсорным вводом и клавиатурой; любое изменение даёт ровно один undo-шаг, повторное событие `change` с теми же значениями не засоряет историю.

## Этап C — настоящий Three.js

1. Перенеси единый `FloorPlan` в `house` или введи `stackedHouse`. На каждый уровень добавь самостоятельные наружные стены и стены комнат, но не создавай полную крышу на каждом уровне.
2. Размещай уровни с вертикальным шагом `STOREY_HEIGHT = 3.2` (при необходимости согласуй с существующей высотой 3.0 м стен). Учитывай текущий масштаб городского участка `unit = .65`.
3. Построй `roofs(plan)`: для промежуточных этажей — разность контуров, на последнем — весь контур. Не рисуй накладывающиеся сплошные крыши: они физически пройдут через верхние стены. Нужны настоящие кровельные участки/террасы с водоотводом и оформлением примыканий.
4. Для `columns(plan)` создай деревянные, каменные или металлические колонны от `fromY` до `toY`. Проверь архитектурную устойчивость **как игровое правило**: колонны должны иметь контакт с ближайшей опорой/землёй, но это не расчёт строительных нагрузок.
5. Лестницы должны иметь настоящую 3D-геометрию марша/площадки и отверстие в перекрытии, иначе игрок увидит лестницу, упирающуюся в сплошной потолок. Нельзя подменять отверстие полупрозрачной текстурой.
6. Камера должна автоматически увеличивать дальний план при росте башни. Для высоких этажей нужны culling/instancing/LOD, чтобы необязательный декор не умножал draw calls. NPC используют только двери первого этажа и не ломаются от новых планов.
7. Уважай режим `low` и `prefers-reduced-motion`. Не создавай новые геометрии каждый кадр: перестраивай сцену только при изменении модели.

## Этап D — хранилище и главы

1. Введи формат v2 и отдельные декодеры `decodeV1` / `decodeV2`. Мигрируй v1 сохранения обеих построек и незавершённый черновик без изменения оригинального ключа `architects-of-time.valley`.
2. Валидируй количество и целостность этажей, ID стен/проёмов/лестниц, стоимость, завершённые задачи и награды. Повреждённый черновик не должен ломать запуск игры.
3. Удержи текущую 001 «Новую долину» как регрессионный сценарий, а новые этажи открой в самостоятельной мастерской/продвинутых заказах.
4. Свяжи поздние задачи с живым городом 002, не создавая параллельные объекты зданий с несовместимой геометрией.

## Приёмка

- 1 этаж: прежние сохранения и тесты не изменились.
- 2 этажа меньшей площади: правильная лестница, крыша над остатком первого, отсутствие «крыши внутри второго».
- Смещённый 2 этаж: рассчитанные колонны видны в 3D и в смете.
- 3 этажа: два лестничных перехода, верхняя кровля, возможные колонны до промежуточного уровня.
- 17 этажей: модель валидна; UI не зависает и адаптирует уровень детализации.
- Undo/Redo, экспорт/импорт и localStorage восстанавливают один и тот же многослойный чертёж.
- GitHub Pages CI: `npm test`, `npm run build`, `npm run e2e`, отсутствие регрессии первых двух заказов.
