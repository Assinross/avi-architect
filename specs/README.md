## Правила сопровождения

1. Любое изменение строительного алгоритма описывается в **003**, любое изменение миссий/мира — в **002**, новое обучение и исторический контент — в **004**.
2. Функция получает статус **«реализована»** только при наличии соответствующего кода. Тесты и CI — доказательство проверяемости, а не замена фактической проверки.
3. Не дублировать движок строительства в свободной мастерской и карьере. Разница режимов — **разрешённые инструменты и правила заказа**, а также отображение 3D.
4. Текущая работа ведётся **без миграций старых сохранений**: актуальный формат допускает сброс прогресса при изменениях схемы. Не вводить требования обратной совместимости, пока пользователь не поручит это отдельно.
5. **Не обозначать незавершённое как готовое**: произвольные контуры, инженерный расчёт, полноценные интерьеры, озвучка и будущие главы остаются TODO.
6. Исходные планы сохранены как исторические записи, например [002 initial proposal](002-living-town/initial-proposal.md) и [002 gap analysis](002-living-town/gap-analysis.md). Их требования не заменяют актуальную спецификацию.

**Примечание:** в проекте есть шаблон `.specify/memory/constitution.md`, но он ещё не заполнен. Этот документ не считается принятой конституцией SpecKit; его заполнение — отдельное архитектурное решение.
